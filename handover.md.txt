Gym Tracker — Handover Document (current as of app v6.1 / sw v44 / schema v14, 2026-07-11)

============================================================
1. WHAT THIS IS
============================================================
A single-file Progressive Web App that is two things fused together:

• A gym workout tracker — logs weight × reps × sets per exercise per day. This is the
  real, load-bearing purpose (the user, Mateusz, is a gym-goer who tracks his lifts).
• A Pokémon RPG built on top of it — every set you log powers a full Pokémon game
  (battle catching, leveling, boss battles, special buildings, an economy with two
  currencies, a Pokédex with official artwork, medals, quests, fishing, a decathlon,
  a battle tower). The workout IS the game engine. It is TWO campaigns: a FireRed
  KANTO campaign and an Emerald HOENN campaign, chosen with a region switcher
  (S.S. Tidal in OPTION, unlocks after the Kanto Champion). Each region is its own
  self-contained save; workout data is shared. As of v6.1 the Hoenn campaign carries
  the FULL Team Magma/Aqua story arc (8 chapters) + twelve special places.

Design conceit: it had to be ONE PWA, not a separate game app, because iOS gives each
installed home-screen app isolated storage — a separate app couldn't read the workout logs.

Live URL:  https://mateuszkrw-coder.github.io/gym-tracker/
Repo:      https://github.com/mateuszkrw-coder/gym-tracker  (GitHub Pages from main branch root)
Current:   app v6.1 “Magma & Aqua”, service-worker cache v44, data schema v14.

4. CORE TECHNOLOGIES
============================================================
• Vanilla JavaScript (ES5-style, one big IIFE) — NO framework, NO build step, NO deps.
• Single HTML file: index.html (~8300 lines) — all HTML + CSS (one <style>) + JS (one <script>).
• localStorage for all persistence (key `gymtracker.v1`). No backend, no accounts, by design.
• Service worker (sw.js) for offline PWA behavior — precaches the app shell + sprites/maps.
  sprites/art/ (Sugimori artwork) and sounds/ are NOT precached — runtime-cached on first use.
• Web Audio API — GBA-style synth SFX in code AND official audio files:
    - sounds/cries/{key}.mp3   : 122 Pokémon cries (Kanto only; Hoenn needs none, locked)
    - sounds/moves/{slug}.mp3  : 139 authentic FRLG attack-move SFX
• SVG — inline for charts, medals, the egg, ferry/rod/gem/weather icons, athlon cups.
• CSS animations — battle choreography, ball throws, travel ferry, VS splash, evolution
  morph, shiny sparkle, weather overlays, slot reels, and (v6.1) the Sootopolis crisis
  (#crisisfx) + Rayquaza descent (#rayfx) overlays.
Rendering model: a single render() swaps #view.innerHTML by `tab`. State in the `state`
object; every mutation calls save() then re-renders. No virtual DOM — template-string HTML
+ event delegation (one global click listener + one input listener for the BOX search).

8. CRITICAL GOTCHAS (read before editing)
============================================================
• BUMP `CACHE` in sw.js on EVERY change (v44 → v45…), or installed phones keep the stale
  version. Then commit AND push — Pages auto-deploys.
• BUMP the app version string in settingsHTML() ("Gym Tracker vX.X") so you can confirm live.
• NO NODE/NPM/PYTHON on either machine. Syntax check = load the preview and probe:
  fetch index.html, extract the <script>, `new Function(src)` in preview_eval —
  parse errors surface there; then execute-probe for runtime errors (see §9).
• ES5 top-to-bottom eval order bites: `var` data tables are assigned at eval time —
  a `X.push(...)` placed ABOVE `var X=[...]` kills the whole IIFE with a blank screen
  and NO console error. Function declarations hoist; data statements cannot.
• REGION TABLES: the content-table globals — TOWNS, TOWN_MAP_XY, WILD_BANDS,
  AREA_SPAWNS, BOSSES, ROAD_LOC, GYMS, RAIDS, RAID_SPECIES, POIS, RIVAL_ROADS,
  TRAINER_CLASSES, NPCQ, DAILY_POOL, DEX_ORDER, FEATURES, and (v6.1) PRIZE_MONS,
  TM_LIST, STONES, STONE_EVOS, FISH_TABLES, FISH_BANDS — are REASSIGNED by
  setRegionTables() based on state.region. KANTO_* captures for the v6.1 shop/fishing
  tables sit NEXT TO their Kanto originals (lines ~5760/6120/6220), NOT next to
  setRegionTables — because `var KANTO_X=X` must run AFTER `var X=[...]` in eval
  order. setRegionTables() only READS them at call time, so its position is safe.
  If you add a per-region table, capture it beside the original and swap it there.
• DEX / MOVESETS / MOVE_TYPES are SHARED SUPERSETS, not swapped. CR_EXT / XP_EXT
  cover ids >151.
• applyImport() sanitizes EACH game object through sanitizeGame(dgame,region).
  Add new game fields inside sanitizeGame — v6.1's poi keys are whitelisted there
  (devon/wx/pyre/magma/aqua/space/origin/sky/trick). game.flags passes through
  WHOLESALE, so story flags need no sanitizer work.
• THE ARC ENGINE: story fights are kind 'arc' with f = chapter*10+step; the wild's
  tr.arc=[ch,step] is validated TWICE (poiStartFight before, poiTrainerWin after)
  against arcStage() AND poiOf(key).f, so stale/replayed fights can't double-advance.
  Chapter completion sets flags.arcN + queues arcScene(N). Chapters 3 and 8 complete
  via page buttons (pyre-summit / sky-wake), not fights. If you add a chapter, keep
  both validations in sync.
• Fight-or-catch floors (pyre/sky) advance in BOTH paths: the wild-faint hook in
  saveLogEntry AND the catch hook in runThrow. Touch both or floors desync.
• State-first, theatre-after: every animated flow (ball throw, slots, travel, athlon,
  fishing, arc scenes, legend catches) decides and SAVES the outcome before the
  animation plays.
• File is BOM-less UTF-8. PowerShell reads need -Encoding UTF8. Use ₽ (not ₱).
  Curly apostrophes (’) inside JS strings are normal here.
• PowerShell here-strings break git commits with embedded quotes — use the Bash tool.
• gh CLI is NOT installed. GitHub API via token from `git credential fill` (Bash):
    TOKEN=$(printf "protocol=https\nhost=github.com\n" | git credential fill | grep '^password=' | cut -d= -f2)
  Deploy verify: poll actions/runs for conclusion=success AND head_sha == your commit,
  then curl the live site for the version string.
• Battle engine is class-based + topmost-scoped: bw()/bq(sel) target the LAST .btwrap
  in the DOM. Don't reintroduce #id lookups. alignBack() sinks the back sprite.
• Building fights are injections into the roadblock engine: poiStartFight → poiWildFor
  builds a wild with a marker; victories resolve in poiTrainerWin (trainers) or inline
  hooks (ghost/pyre/sky/legend wilds). Markers are validated against the building's
  CURRENT floor/streak/stage.
• Night theme skips ALL skins by design (applySkin returns early) — building palettes,
  quest biomes, the Emerald skin AND the v6.1 Hoenn building palettes are DAY-only.
  Do not restyle night. (Verified again in v6.1.)
• Modal queue pops with ~180ms delay — drive modal chains step-by-step when testing.
• Weather is PURE ART (locked). The v6.1 forecast board is display-only too.
• Editing index.html via an external script invalidates the Edit tool's read-state —
  re-Read before the next Edit. Grep for call sites after removing/renaming anything.
• ART SOURCING: probe per machine (§2). Working routes by preference:
    1. PokeAPI mirror on raw.githubusercontent.com/PokeAPI/… (sprites + data CSVs)
    2. pret/pokeemerald decomp (trainers: front_pics 64×64, MakeTransparent corner px;
       tile-based graphics there are palette-stripped — skip)
    3. bulbapedia.bulbagarden.net/wiki/Special:FilePath/<File>.png with browser UA
       (works on machine A; machine B must use Wayback: web.archive.org/web/2023id_/…)
    4. Serebii pokearth (serebii.net/pokearth/maps/hoenn-em/{id}.png)
    5. pokemon.fandom.com API — MUST append &format=png or you get WebP
  Emerald interior/location screenshots are named "<Location> E.png" (or "1F E",
  "entrance E", "SE" for Sapphire/Emerald shares) on Bulbapedia — probe with the
  MediaWiki API (action=query&prop=images) when unsure.
  Resize/crop locally with .NET System.Drawing (PS 5.1). $pid is RESERVED in PowerShell.
